# OpenPriceHub 模型成本计算器统一验收报告

版本：v1.0.0

日期：2026-11-13 UTC

状态：P0—P4 计算器开发及本地测试完成，等待用户统一验收。

范围：现有 `/zh/calculator`、`/en/calculator`，保留快速模式、详细模式、本地存档和 JSON 导入导出。

## 1. 交付范围

沿用 React、现有组件、路由及本地存储架构，增量扩展计算器。P0 的分类、单位、参数隔离及 P1 的完整套餐购买计算保留。首页原有功能与广告预留经过回归检查。

本报告中的 P1 指计算器整包购买阶段，与数据库 P1、Mock First P1 是不同工作范围。当前交付不代表整个 OpenPriceHub 平台已经完成。

## 2. 价格规则与计算

支持 14 种单位：每张图片、每个视频、每秒、每分钟、每字符、每首歌曲、每次生成、每积分，以及输入、输出、缓存 Token 各自的每 1K 和每 1M 单位。

- 输入 Token 与缓存 Token 分开填写，不默认重复计算。缺少本次请求所需的价格会阻止完整成本计算；未知价格不等于免费。
- 图片、视频、TTS、音乐、LLM/API 分组；单位、场景、参数及使用周期不一致时不进行单位成本排名。
- 同模型不同服务商可在相同条件下比较。用户指定统一使用量后可以比较总成本，但不据此混排不同维度的单位价格。
- 支持免费额度、超额单价、分段累计阶梯、整量阶梯、固定月费、年费、最低消费，以及模型参数对应的独立价格规则。
- 分段阶梯逐段累计；整量阶梯使用命中档位计算全部收费数量。阶梯边界使用实际计量数量，1K/1M 单位价格按对应倍率换算。
- 阶梯与独立超额价格同时填写、阶梯重叠、缺少档位价格、超过有限档位上限等情况会提示错误，不默认补齐。
- 月订阅绑定月用量；年订阅需明确额度按月还是按年。按月额度的年订阅在月场景中展示全年预付现金与当月分摊消耗，不推断全年超额用量或额度结转。
- 视频数量与每条时长、歌曲数量与单首时长可以推导总时长；没有明确条件时不强行换算字符与分钟、歌曲与生成次数。

存在固定费用、免费额度、阶梯或整包购买时，不将总成本伪装为固定单位单价。结果展示预计消耗成本、实际购买金额、购买套餐数量及剩余积分；不可公平比较的结果附有限制提示。

### 积分与真实购买金额

以模拟条件“99 CNY / 1200 积分，每张 20 积分，生成 100 张”为例：

| 项目 | 结果 |
| --- | --- |
| 所需积分 | 2000 |
| 套餐数量 | 2 |
| 实际支付 | 198 CNY |
| 剩余积分 | 400 |
| 预计消耗成本 | 165 CNY |

条件是套餐明确可叠加、属于同一积分池、没有额外购买限制，且从零余额开始购买。

另支持同池免费积分、明确的现金超额积分价格和购买最低金额：不可叠加时，购买一个套餐后额外 800 积分按 0.1 CNY 收费，实际支付为 179 CNY。叠加购买与现金超额策略同时启用会要求明确策略，不猜测最优方案。最低消费增加支付金额但不凭空增加积分。免费积分 100、叠加购买且无现金超额时，支付 198 CNY、剩余 500 积分、预计消耗 156.75 CNY。

不同积分池不会合并。购买上限、适用模型限制及未知叠加条件会影响可购买性。计算的是本次从零余额出发的新购买报价，不是既有账户余额、跨套餐混合买入优化或订阅账单管理。

## 3. 汇率管理

支持手动汇率、基准币种切换、增加币种、目标币种、汇率来源及更新时间。有效编辑立即触发所有结果重算；无效编辑保留上一次有效结果并提示。

基准切换保留精确比例，避免反复换基准导致金额漂移。新增币种必须填写正汇率，不默认汇率为 1。没有已知汇率时不虚构换算结果。

“自动汇率”依照原需求的“后续”安排保留禁用入口。本次不调用实时汇率服务，示例汇率明确标记为模拟数据，没有核验时间的旧设置展示为未知。

## 4. 快速模式、详细模式与 JSON

快速模式允许临时输入价格和使用量；详细模式维护网站、模型、套餐与参数规则，二者共用计算引擎。

“保存到详细模式”先预览，再追加独立的网站、模型、套餐和规则，不按名称猜测身份或合并已有记录。已有详细存档保留设置；空存档采用快速模式设置。新增币种通过双方已知公共币种换算，没有汇率桥接条件时停止转存并提示。

JSON 导出使用 `openpricehub-calculator` 格式、外层版本 2，内部存档版本仍为 1，并兼容旧版直接导出的版本 1 数据。导入检查格式、版本、模式、引用关系、ID、价格、单位、阶梯、汇率和容量等条件。

导入预览展示条目数量、前五个记录名称、目标币种、用量周期及警告。确认前不会覆盖；取消保持原存档。确认替换或载入完整示例之前，保存上一次本地存档，支持预览并恢复备份。不支持的版本或无效数据不会覆盖存档。文件大小限制 2 MB，集合长度上限 5000。

## 5. 精度与兼容性

价格和金融排序采用精确十进制及分数运算；新增输入保存精确十进制文本，同时保留旧数字字段兼容存档。旧数据已丢失的输入精度无法恢复。十进制输入最多 30 位数字、12 位小数，离散数量要求安全整数。图表沿用数值近似展示；财务金额及排序使用精确计算结果。

旧的快速音频比较入口保留，其完整模型计算器链接按 TTS/音乐分类进入本次工作区；没有宣称旧音频快捷工具已经整体替换为新引擎。原有本地数据键、模式切换和工作区筛选继续保留。

## 6. 验收操作

1. 打开 `/zh/calculator` 或 `/en/calculator`，进入快速模式。
2. 点击“载入完整计价示例”，查看导入预览后确认。该操作会替换当前快速存档并备份原值。
3. 检查 10 条 SIM 模拟记录：图片阶梯、图片积分、视频按秒、视频按条、TTS 字符订阅、音乐按首、API 输入/输出/缓存 Token、图片最低消费、图片免费额度和图片年订阅。
4. 图片数量改为 100，验证上方 99/1200/20 的整包购买结果。默认完整示例为 150 张，此时需要购买 3 个套餐。
5. 修改免费额度、超额价格、阶梯模式、订阅周期和模型参数，检查结果及不可比提示。
6. 修改手动汇率、切换基准和目标币种，确认所有可换算结果同步更新。
7. 导出 JSON，尝试导入预览后取消、确认及恢复备份；未知版本应被拒绝。
8. 将快速记录保存到详细模式，确认原记录保留、新记录追加，继续编辑套餐和规则。
9. 在桌面及手机宽度检查中英文界面。手机结果卡直接展示支付、消耗及积分余额，完整表格仍可横向浏览。

全部示例为虚构的真实计价结构测试数据，明确标记为模拟数据，不是官方报价；不会写入 D1。
