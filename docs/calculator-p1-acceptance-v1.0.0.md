## 2. 购买成本

结果分别展示：

- 单位消耗成本（原币种及目标币种，分项展示）。
- 本次预计消耗成本。
- 本次消耗积分。
- 需要购买的完整套餐数。
- 本次购买金额（预计），保留原币种金额及换算结果。
- 剩余积分及所属积分池。

「对比指标」可选择预计消耗成本、购买金额或单位成本。每行单独计算重复购买同一种套餐的结果，不混合不同套餐额度，也不声称找到了混合套餐组合的全局最优价格。

### 验收例子

假定 99 CNY / 1200 积分，每张消耗 20 积分，使用 100 张；已确认可叠加、全部额度可用于本次使用，没有额外限制，从零余额新购：

| 项目 | 结果 |
|---|---|
| 每张消耗成本 | 1.65 CNY |
| 消耗积分 | 2000 |
| 本次消耗成本 | 165 CNY |
| 完整套餐数量 | ceil(2000 / 1200) = 2 |
| 本次购买金额 | 198 CNY |
| 剩余积分 | 400 |

对比另一个 39 CNY / 400 积分套餐：本次消耗成本为 195 CNY，购买 5 包支付 195 CNY、余额 0。前者单位消耗更便宜，后者本次整包购买更便宜；两种排序已经分别验证。

## 3. 条件与数据安全

### 快速模式

积分条目增加可选积分池名称、购买周期、可叠加状态和最多购买数量。可叠加为三态：未确认 / 已确认可叠加且无其他使用限制 / 不可叠加。

旧记录没有这些字段时保持未确认，不自动升级为可叠加。消耗折算值可以查看；购买金额未知的记录不作为可实现的最低价参与排名。

### 详细模式

套餐增加积分池及购买条件；模型规则增加使用积分池和明确适用套餐多选。只有套餐和规则属于同一网站、用户明确确认适用且积分池相同，才能生成购买报价。

旧规则未确认适用套餐时给出原因；不会为了生成报价，把该网站所有积分套餐视为已支持该模型。旧候选行保留用于查看与补充信息，未确认的行不参与排名。

删除套餐时清理其规则适用关联；将套餐移动到另一个网站时移除原网站的不兼容适用关联，不重新猜测关系。

### 失败行为

| 条件 | 行为 |
|---|---|
| 未确认能否叠加 | 购买金额未知，不展示为 0 |
| 不可叠加且一个套餐额度不足 | 无可行购买报价，不参加排名 |
| 所需套餐数超过限购 | 无可行购买报价，不通过减少用量生成低价 |
| 上限为负数、0、非整数等无效值 | 明确阻断 |
| 缺少价格、积分额度或必要使用费率 | 不当作免费 |
| 模型适用范围未确认或积分池不同 | 明确阻断，不混用积分 |
| 不同购买周期/承诺 | 购买金额分别分组，不把年付与月付混排 |
| 周期未知或自定义含义未明确 | 可展示条件下计算出的金额，但不参加购买金额排名 |

从零余额按需新购不等于已经订阅的续费账单。零用量不购包，且不参加最低成本排名；不推测余额结转、退款、税费、失效日期或额外权益。免费套餐、超额、阶梯、最低消费等仍属于 P2。

## 4. 精度与兼容

复用 Mock First 已有 BigInt 十进制有理数实现，金额、积分消耗、汇率转换和整包向上取整在内部保持精确；整包数量在任何展示舍入之前计算。输入/输出 Token 费用分别计算后按使用量累加。

财务结果和单价新增十进制文本及精确分子/分母；排序使用精确值，展示最多 12 位小数。关键金额小于展示精度时显示阈值提示；图表比例仅作视觉近似。兼容保留旧数字型结果字段，不再用旧六位小数显示值反推套餐数量。

原表单及 JSON 仍以 number 存储输入，适配时使用已存数字的十进制表示，并展开科学计数格式再进行精确计算；不会恢复旧数据在保存之前已经丢失的精度。当前十进制解析上限为 30 位数字、12 位小数，超出支持精度的输入不生成报价。后续若需要任意高精度输入契约，应在对应类型演进阶段单独处理。

保留 JSON version 1 和原 localStorage 键，新增字段可选。详细模式修改本次用量及结果币种后，也会同步保存到导出状态，确保重新导入可以复现购买结果。新版 JSON 导入预览及完整版本策略仍属于 P4。
