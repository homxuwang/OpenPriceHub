# 产品详情、比较与平替动态更新方案

版本：v1.0.0

日期：2026-11-13 UTC

状态：方案草案，未启用定时任务、修改应用代码、执行数据库迁移或部署。

## 当前检查结论

- `src/frontend/App.tsx` 中 `tools/:slug`、`compare` 为 Soon 占位页，未接入平替页面路由。
- `src/frontend/data/index.ts` 的工具查询读取本地 Mock，不能通过更新 D1 自动更新主流程。
- `src/frontend/catalog/` 保留目录扩展页面与数据上下文，可评估复用业务模块，样式继续使用现有 UI。
- `src/worker/routes/catalog.ts` 已有目录、产品、平替和历史读取，以及受管理员密钥保护的校验与发布接口。
- `migrations/0003_product_catalog.sql` 定义来源、套餐、价格组件、历史、同步日志、平替关系及目录版本等结构；文件存在不代表远程 D1 已应用，需要只读核对实际数据库。
- Worker 当前只有 fetch 入口，wrangler.toml 没有 Cron。D1/KV 配置仍有占位值，不能推断生产服务已具备运行条件。
- 现有目录校验和价格结构不等同于新计算器的全部能力；连接前需做价格组件适配及精度审查，不得强行映射不支持的计价规则。

## 推荐节奏

初期每天一次全量来源检查，稳定后再增加晚间重点检查；不是每天必须生成或修改内容。

| 模式 | 北京时间（UTC+8） | UTC Cron 示例 | 范围 |
| --- | --- | --- | --- |
| 一天一更 | 每日 09:00 | `0 1 * * *` | 全部已配置来源 |
| 一天两更 | 每日 09:00、21:00 | `0 1,13 * * *` | 上午全量；晚上高频来源、失败项及待发布项 |

Cron 使用 UTC；执行时间是启动检查的时间，不保证立即完成发布。上午和晚上可以共用调度入口，通过当前时段选择不同任务集合。实际频率按每个来源配置，不对所有网站机械抓取两次。初始建议观察 7 天日志、成功率及人工审核负担后决定是否开启两更。

Cloudflare 官方说明：https://developers.cloudflare.com/workers/configuration/cron-triggers/

## 页面如何动态更新

三类页面使用同一已发布目录版本及同一数据访问层，不维护三份独立报价：

- 产品详情：基本信息、模型、渠道、套餐、计价条件、官方来源和核对时间。
- 独立比较：按用户选择的产品、套餐与统一用量调用现有计算引擎，绑定同一个目录版本。
- 平替页面：维护有方向的功能/场景关系，价格变化后只重算成本差异，不自动虚构相似度或质量排名。

建议路由：`/:lang/tools/:slug`、`/:lang/compare`、`/:lang/compare/:pair`、`/:lang/alternatives/:slug`。沿用中英文前缀、现有导航、卡片和表格样式。比较支持查询参数选择多个产品；有独立内容的固定对比链接才进入 Sitemap。

页面获取数据带 `revision`、`publishedAt`、`lastCheckedAt`、`priceVerifiedAt` 与来源状态。打开页面时检查目录版本；长时间停留页面每 5 分钟检查一次，变化时提示刷新，避免用户填写中的用量被覆盖。已保存计算器档案保持原值，可明确选择更新价格后重新计算。

浏览器和边缘缓存建议以 5 分钟为目标上限，采用版本标识及重新验证；这是计划目标，需实现和测试。页面应明确展示正在使用旧缓存或备用快照，不能将内置旧快照伪装为在线最新数据。

## 更新流水线

1. **调度**：读取启用的来源和频率，建立本次任务及幂等标识。用 D1 唯一约束和带过期时间的任务租约防止定时与手动任务重复发布。
2. **采集**：优先官方 API、官方结构化数据；其次稳定的官方价格页面。每个来源使用独立适配器，支持 ETag/Last-Modified、超时及限速。需要登录、地区差异或复杂动态页面时进入人工更新，不无限扩大抓取架构。
3. **解析**：保留原始币种、周期、单位、模型/渠道、额度与参数。空价格为未知，不能写 0；原始金额使用精确文本或定点设计，禁止使用浮点重算后直接发布。
4. **差异检测**：区分抓取时间、价格核对时间、实际变更时间。只有完整识别到对应价格区块且规则验证通过，才能刷新价格核对时间。304 或页面哈希相同可以复用之前的有效解析；仅 HTTP 200 或抓取成功不能刷新核对时间。
5. **候选与审核**：先保存候选版本，再进行结构、单位、适用模型、额度及变更幅度校验。初期所有价格变化需人工确认；无变化且可完整验证的记录自动记录检查结果。后期可为稳定 API 配置自动发布白名单。新增套餐、单位变化、消失价格、异常降至免费和大幅变化继续人工审核。
6. **发布**：复用现有校验/发布服务，在规模允许时使用 D1 batch 原子发布目录版本、索引及历史。不能调用公开写接口绕过鉴权。规模超出单次批处理能力时改为分批写不可见候选，完成后切换当前版本；此项按实际数据规模决定。
7. **派生刷新**：对受影响产品重算比较与平替成本；关系仍需有效的功能依据。没有可比价格时显示“无法直接比较”，不保留失效的节省百分比。
8. **缓存与 SEO**：发布后更新数据版本与缓存验证标识。动态产品/比较/平替页面应由 Worker 输出与可见内容一致的 metadata、Canonical、结构化数据；Sitemap 从有效已发布内容生成。仅靠当前构建时静态内容不能实现完整动态 SEO。
9. **记录与恢复**：记录每个来源成功、无变化、待审、失败、耗时和错误。发布失败保留上个有效版本。回滚是重新发布旧快照形成新版本并留审计记录，不删除历史。

## 状态及过期策略

建议分别展示“最后检查”“价格核对”“价格变更”，不把每日抓取时间包装成每日价格变动。

| 情况 | 行为 |
| --- | --- |
| 无变化且已有效核对 | 更新时间戳，不新增虚假价格变化历史 |
| 新价格待审核 | 继续显示上一已发布值，标注待更新，不提前套用新价格 |
| 单个来源失败 | 保留原值及原核对时间，记录失败；其他来源继续 |
| 超过来源有效期 | 显示过期标记，从最低价及节省结论中排除 |
| 缺少价格 | 显示未知，不当成免费 |
| 官方套餐删除 | 候选标记停用，确认后从当前可购方案中移除，保留历史 |
| 无足够功能依据 | 可展示相关工具，但不声称是低价平替或给出质量评分 |

初始可配置有效期为普通订阅 7 天、高变动 API 单价 3 天；这是运营建议，不是当前系统已启用的规则。来源可单独覆盖，过期的判定和排名必须使用同一规则。页面状态与元数据/结构化报价保持一致。

## 最小化 D1 扩展

先只读核查生产实际 schema。优先复用现有 `data_sources`、`data_sync_logs`、`catalog_revisions`、`price_history`、`alternatives` 和用户提交结构。

可能需要的增量字段/实体，不机械新建全部目标表：

- 来源配置：适配器、更新间隔、有效期、启用状态、官方来源地址、ETag、Last-Modified、最后尝试/成功时间。
- 同步任务：唯一任务标识、来源、调度时间、状态、租约、重试时间、错误摘要及候选版本。
- 候选审核：基准版本、差异、解析证据、状态、审核人、审核时间；避免把用户提交表强行当作所有来源同步任务表。
- 发布元信息：基础版本及冲突检测、触发来源和操作者。候选审核时若发布基准已变，必须重新计算差异，不能用旧完整快照覆盖其他已批准更新。

模型/渠道/套餐身份不明确时进入待确认，不靠名称强制匹配。所有必要数据库调整在实现阶段生成兼容 Migration，不能直接改生产旧表或覆盖数据。

| A：接通主流程 | 原 UI 下的详情、独立比较、平替页；统一读取发布目录；Mock 与真实数据明确区分 | `src/frontend/App.tsx`、`data/`、`catalog/`，新增或复用页面 |
| B：候选与人工发布 | 来源配置、差异预览、审核、历史、过期判断、兼容与精度适配 | `src/shared/catalog/`、`src/worker/routes/catalog.ts`、必要的新增 Migration |

## 验收条件

- 一次更新可以同步反映在详情、比较和平替页面，三者显示相同目录版本。
- 一更/两更时区正确；重复调用幂等；超时任务不会永久占锁；并发候选不会覆盖其他更新。
- 来源失败或审核拒绝不会改变公开报价；旧价格按有效期正确标记。
- 价格不变不产生价格变更历史，检查成功不冒充价格变更。
- 不同币种、单位、渠道、套餐及参数条件保持准确；无法适配现有计算引擎的规则明确拒绝计算。
- 过期或未知价格不参与“最低价”“省多少钱”结论；Affiliate 不影响排名。
- JSON/localStorage 保存的计算器数据不会被后台发布覆盖。
- 动态 metadata、Sitemap、结构化数据与可见已发布数据一致；无价值筛选组合不批量索引。
- 测量每日来源请求数、读写量、失败率和执行时长后再决定是否扩至两更；本方案不承诺未测量的托管费用。
